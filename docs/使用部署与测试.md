# TraceForge 使用、部署与测试

## 运行目录与服务

项目位于 `D:\systemDir\Documents\ChatGPT\agent_program`。默认服务地址：工作台与API为127.0.0.1:8000，资料MCP为127.0.0.1:8001/mcp，Ollama为127.0.0.1:11434，Milvus gRPC为127.0.0.1:19530，Milvus健康端点为127.0.0.1:9091/healthz。

Python依赖由uv.lock固定，前端由package-lock.json固定。实际兼容组合包括Python3.12、PyTorch2.8.0+cu128、FastMCP3.0.2、MCP1.x、Ragas0.4.3与langchain-community0.4.1；具体全部版本以锁文件为准。

Docker在现有WSL Ubuntu中运行。Windows启动脚本启动一个后台WSL保活进程，避免Linux服务在WSL空闲关闭后断连。它不执行周期性任务。停止时只停止应用服务与已登记的保活进程，数据保留。

## 页面操作

### 诊断工作台

粘贴完整报错、最后若干栈帧、预期行为和已做过的检查。选定项目后，Agent才能读取其依赖和配置。可添加日志或截图，截图识别只记录可见内容。

“知识问答”使用资料路径；“故障诊断”可并行分析日志、项目和资料。结果区显示结论、支持证据与待验证假设。点击引用查看原文；右侧可切换证据、工作流与事件。

审核卡列出修改内容或命令，选“修改方案”可编辑结构化提案，保存后重新审核。拒绝会跳过该动作。暂停等待审核时可关闭浏览器，重开后从最近诊断进入原任务。

### 知识库

上传支持的文档或粘贴公开HTTPS链接。状态依次为queued、indexing、ready；失败保留具体原因。校正识别文本后重新索引。重建使用稳定文档ID，不会重复插入相同切片。

公开URL不使用浏览器登录态。私人飞书课程用于本项目设计，未复制到初始知识库。用户可以上传自己有权使用的项目资料。

### 检索实验

运行同一问题，分别比较稠密、BM25、混合召回。观察专有名词、错误码与口语化问题的区别，再开启查询改写、HyDE、多跳或重排。页面保留多路候选、融合排名、最终证据和耗时。

分数属于不同阶段，不应把BM25、余弦与重排分数直接当成同一种置信度。缺乏证据时应补充日志、版本或资料。

### 项目与工具

登记具体项目目录，查看可读文件与脱敏内容，检查两个MCP服务连接。任意命令先生成审核卡，在Docker项目副本执行。Python、Node和Java/Maven镜像分别提供对应环境；默认没有网络。

执行记录保存退出码、输出、差异、备份和复验结果。配置回滚只覆盖仍与修复版本一致的文件；文件再次变化后需人工比较备份。容器生成的变更可再次提交审核，不自动写回项目。

### 评估中心

默认30个原创参考案例，比较稠密基线、混合召回和混合加重排。可只运行检索指标，或启用全部六项Ragas。评估使用DeepSeek作评审、本地Ollama作答案相关性嵌入；并发限制为2。

结果包含Recall@5、MRR、nDCG、P50/P95、六项分数、实际回答、参考答案、有序上下文和失败信息。评审失败显示空值与原因，不按0分或通过处理。noise_sensitivity越低越好；其余指标越高越好。

这些原创案例用于学习和回归，不能代表生产项目的总体准确率。加入真实日志及独立参考答案后，再评估业务效果。目标Recall@5≥0.80、Faithfulness≥0.90；实际结果见测试报告。

## 可复现故障演示

`examples/python`的config.json故意把json误写成jsno，容器运行demo.py产生真实ModuleNotFoundError。

`examples/node`的代理目标故意指向9999，demo.mjs检查与实际后端8000的契约。

`examples/java`是实际Spring Boot/JDBC应用，JDBC端口误写3307，MySQL服务内部端口3306；健康接口初始返回500，修复并重启后应返回database=1。

`examples/deployment`的Nginx上游端口误写8001，实际HTTP后端为8000；代理初始返回502，修复并重启后应返回200。

登记演示目录：

```powershell
.venv\Scripts\python.exe scripts\setup-demos.py
```

本机演示配置已在闭环测试中修复。再次制造故障可执行 `scripts/reset-demos.py`，随后通过项目与工具提交对应服务重启审核。该脚本仅修改仓库中的四个演示配置。

Java演示需要构建jar并启动`scripts/demo-compose.yaml`。MySQL演示口令在忽略提交的data/demo-secrets.env中，未写入模型读取的配置。验证脚本只修改这些演示项目与测试临时目录。

本机现有演示可随工作台启动：

```powershell
.\scripts\start.ps1 -SkipBuild -WithDemos
```

重新构建Java演示：

```powershell
wsl -d Ubuntu -u root --exec docker run --rm -v /mnt/d/systemDir/Documents/ChatGPT/agent_program/examples/java:/workspace -w /workspace maven:3.9-eclipse-temurin-21 mvn -B -q -DskipTests package
```

若工作台已运行，启动脚本会保留当前实例；修改后端配置后先停止再启动。

## 部署排错

- Python包下载TLS失败：检查进程代理与国内包源。CUDA wheel仍从官方PyTorch源获取；脚本在本机使用已验证的直连路径。
- Docker Hub拉取失败：检查Docker daemon的网络，而不仅是浏览器。`configure-docker-proxy.sh`使用已验证的现有Windows代理，地址依据WSL默认网关计算。
- Milvus启动报`panic: etcdserver: leader changed`：旧的内置etcd恢复时存在启动竞态。现配置使用独立etcd3.5.33，复用原元数据目录，等待etcd健康后再启动Milvus；重新运行`start.ps1 -SkipBuild`即可恢复依赖，即使后端已经运行。
- etcd健康但Milvus报`failed to create etcd client: context deadline exceeded`：检查Docker网桥与转发规则。本机现通过共享网络空间和`127.0.0.1:2379`连接etcd，避免该链路依赖网桥转发。健康状态采用实际数据库调用，并可运行`scripts/check-milvus.py`验证Windows到数据库的RPC连接。
- Windows能打开页面但Milvus断连：检查WSL保活进程、容器健康状态与19530端口。
- MCP导入RequestContext失败：使用本项目锁定的SDK组合，避免未经验证升级到MCP2.x。
- Ragas导入vertexai失败：使用锁定的langchain-community0.4.1，不创建伪模块或修改第三方包源码。
- 截图识别或模型鉴权失败：在系统设置检查DeepSeek与.env配置；日志中不应显示密钥。
- 旧审批报过期：重新打开任务并审核新预览，或补齐已经变化的配置。

## 数据备份与恢复

停止后端后复制data中的两个SQLite文件、上传解析数据与backups。Milvus和独立etcd共用命名卷traceforge_traceforge_milvus，备份时先用项目Compose停止这两个容器，再导出卷；恢复到相同版本后检查集合和健康状态。

任意命令副本位于data/sandbox，可按执行记录保留或在确认范围后清理。停止脚本不删除任何数据卷，不更改原有学习项目和模型权重。模型、SQLite、Milvus和UI状态分别验证，不能仅凭页面可打开就认定全部链路健康。
